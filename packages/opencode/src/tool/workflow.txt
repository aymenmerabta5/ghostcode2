Discover, run, and manage long-running workflow programs in opencode. A workflow is a
TypeScript/JavaScript script the runtime executes in the background: it fans out subagents with
phases, parallel execution, verification agents, and durable resumable state.
Workflows live in `.opencode/workflows/` (project) and `<global-config>/workflows/` (global).
Project workflows win on name collisions.

# QUALITY-FIRST POLICY (TOKENMAXXING — READ FIRST)
Cost is NOT a constraint. Workflows exist to produce the best possible result, whatever it takes.
- NEVER downgrade model, effort, agent count, or verification depth to save tokens or money.
- Default effort is "max" for reasoning-heavy agents (planning, verification, synthesis, judging)
  and "high" for mechanical agents (listing files, extraction, formatting). Never below "high".
- Default to the strongest available model. Only route a phase to a smaller model when speed
  genuinely matters more than quality for that specific step — never to save cost.
- Verification is MANDATORY, not optional. Every finding/claim/output gets at least 3 independent
  adversarial verifiers; a finding survives only if ≥2 support it.
- Prefer MORE agents over longer prompts: fan out per-file, per-claim, per-angle. If in doubt
  between 10 agents and 100 agents, use 100.
- Iterate until dry: keep running discovery/fix rounds until 2 consecutive rounds produce nothing
  new — never stop after one pass because "it's probably fine".
- Add a completeness critic and/or judge panel before every final report.
- Do NOT set budgets unless the user explicitly asks for a cap. Unbudgeted runs are the default
  and the intended mode.

# WHAT A WORKFLOW IS
- A file exporting a literal-only `meta` object and a `run(args, ctx)` function.
- Runs in the background: `start` returns a run ID immediately; watch with `inspect` or the
  /workflows dashboard. Intermediate results live in script variables and phase data — NOT in the
  main context window.
- Scale: up to 1000 agent() calls per run; min(16, cpuCores-2) execute concurrently, rest queue.
  This concurrency cap is a throughput limit, not a quality limit — queue as many agents as the
  task deserves.

# WHEN TO USE
Use a workflow when the task needs more agents than one conversation can coordinate, or when the
orchestration itself should be a rerunnable artifact: codebase-wide audits, N-file migrations,
research with cross-checked sources, fix-until-green loops.
Do NOT use a workflow for a single subagent's worth of work (use the task/subagent tool) or for
reusable instructions without orchestration (use a skill).

# FILE FORMAT (canonical example)
// .opencode/workflows/audit-routes.ts
export default {
  meta: {
    name: "audit-routes",                       // required, ^[A-Za-z0-9_-]+$, must match filename
    description: "Audit route handlers for missing auth checks",
    whenToUse: "When auditing API routes for auth",
    phases: ["discover", "audit", "verify", "report"],
    arguments: { dir: { type: "string", default: "src/routes" } },
  },
  async run(args, ctx) {
    ctx.setPhase("discover")
    const found = await ctx.agent({
      prompt: `List every .ts file under ${args.dir}. Return {files: string[]}`,
      schema: { type: "object", required: ["files"],
                properties: { files: { type: "array", items: { type: "string" } } } },
      label: "discover-files",
      effort: "high",
    })

    ctx.setPhase("audit", { files: found.data.files })   // payload is persisted + shown in dashboard
    const audits = (await ctx.parallel(
      found.data.files.map(file => () =>
        ctx.agent({
          prompt: `Audit ${file} for missing auth checks. Be exhaustive — report every suspicion. Return {file, issues: string[]}`,
          schema: { type: "object", required: ["file", "issues"],
                    properties: { file: { type: "string" },
                                  issues: { type: "array", items: { type: "string" } } } },
          label: `audit:${file}`,
          effort: "max",
          onError: "null",
        })),
    )).filter(Boolean)

    // MANDATORY verification: 3 independent adversarial verifiers per claim, survive on >=2 support
    ctx.setPhase("verify")
    const claims = audits.flatMap(a => a.data.issues.map(issue => ({ file: a.data.file, issue })))
    const verified = (await ctx.parallel(
      claims.map((c, i) => () =>
        ctx.parallel([0, 1, 2].map(k => () =>
          ctx.agent({
            prompt: `Adversarially verify (lens ${k}: ${["correctness", "exploitability", "reproduction"][k]}): does ${c.file} really have issue "${c.issue}"? Read the file and try to REFUTE it.`,
            schema: { type: "object", required: ["supported", "reason"],
                      properties: { supported: { type: "boolean" }, reason: { type: "string" } } },
            label: `verify:${i}:${k}`,
            effort: "max",
          })
        )).then(vs => ({ ...c, votes: vs.filter(Boolean).map(v => v.data) }))),
    )).filter(Boolean)
    const surviving = verified.filter(v => v.votes.filter(x => x.supported).length >= 2)

    ctx.setPhase("report")
    const critic = await ctx.agent({
      prompt: `Completeness critic: given these confirmed findings ${JSON.stringify(surviving)}, what is MISSING? What did the audit likely overlook?`,
      label: "completeness-critic",
      effort: "max",
    })
    const report = await ctx.agent({
      prompt: `Write a ranked report from these verified findings: ${JSON.stringify(surviving)}. Append gaps raised by the critic: ${critic.text}. Cite files.`,
      label: "report",
      effort: "max",
    })
    return { report: report.text, verified: surviving.length, rejected: verified.length - surviving.length }
  },
}

# HARD RULES
- meta is statically analyzable: literal values only (strings, numbers, booleans, arrays, objects).
  Computed values in meta fail parsing.
- meta.phases must exactly match every setPhase() call. An unknown phase title THROWS
  InvalidPhaseError at runtime (strict default; set meta.phaseValidation: "warn" to relax).
- Determinism: Date.now(), Math.random(), and no-arg new Date() are REJECTED by the source lint —
  they break resume caching. Pass seeds/timestamps via args or compute them inside an agent.
  Escape hatch: meta.allowNondeterminism: true.
- The script itself cannot touch fs/network/process (lint-banned: fs, child_process, net, http,
  fetch, Bun.spawn, process.env, ...). Agents, ctx.shell, and ctx.tool do that work.
- Global style (bare top-level `await agent({...})`, `parallel`, ...) is supported with identical
  signatures, but prefer the `ctx.*` style for anything nontrivial.

# CONTEXT API
- ctx.setPhase(name, data?): advance the phase. `data` is persisted (phase_data) and shown in the
  dashboard. Returns the previous phase's data. Payloads are frozen — treat them as immutable.
- ctx.getPhase(name) / ctx.getAllPhases(): read any phase's stored payload.
- ctx.state: persisted key-value store for cross-phase counters and accumulation.
- ctx.agent({prompt, label, schema?, model?, effort?, agentType?, phase?, isolation?, onError?})
  → {text, data}. `schema` is standard JSON Schema; output is extracted, validated with ajv, and
  automatically repaired via a follow-up message before StructuredOutputError is thrown.
  effort: "low"|"medium"|"high"|"xhigh"|"max" — default to "max" for thinking work, "high" minimum.
  onError: "null" returns null instead of throwing.
  ALWAYS give a unique, stable label (e.g. `verify:${id}`) — it drives caching and skip.
- ctx.parallel(tasks, {concurrencyLimit?}) → (T|null)[]: fan-out with barrier; failed tasks yield
  null — always .filter(Boolean). Max 4096 items per batch. Omit concurrencyLimit to let the
  engine run as wide as the machine allows.
- ctx.pipeline(items, ...stages, {concurrencyLimit?}): chained stages, each stage is
  (prevResult, originalItem, index) => Promise<next>.
- ctx.workflow(name, args?): run a child workflow inline; child agents/logs are attributed to the
  child structurally in the dashboard.
- ctx.shell(cmd, {timeout = 60000, cwd?}) → {output, exitCode}.
- ctx.tool(name, args) → real tool execution (read, grep, glob, ...) through the same registry as
  normal sessions, with subagent permissions. Optionally restrict via meta.tools: string[].
- ctx.question({question, options?, timeout = 600000}) → {answer}: pauses the run for a human
  answer (⏳ in dashboard; answered via the answer action).
- ctx.log(msg): narrator line in the dashboard, interleaved chronologically with agents.
- ctx.budget: {total, spent(), remaining(), tokensTotal, tokensSpent(), tokensRemaining()} —
  informational tracking. total/tokensTotal are Infinity unless the user explicitly set a cap.
- isolation: "worktree" on an agent runs it in its own git worktree/branch (wf/<run>/<label>);
  the result reports {branch, changedFiles}; the main tree is untouched. Merge explicitly with
  ctx.mergeWorktree(result) — it throws a structured error on conflict. Use it whenever parallel
  agents edit files; correctness over disk cost.

# TOOL ACTIONS
- list: all discovered workflows (builtins + project + global) with name, description, valid, error.
  Always call first.
- read: get a workflow's source by name. Use before writing a similar one.
- start: run by name with {args?, resume_of?, invalidate_agents?, budget?}. Returns run ID
  immediately. Also accepts inline `source` for ephemeral runs. Args are coerced per
  meta.arguments. Do NOT pass budget unless the user explicitly requested a cap.
- inspect: full run JSON — status, current_phase, phase_data, logs, agents (label, status, cost,
  cached, output...), result, pending_question.
- wait: block until the run finishes or timeout. Use sparingly; prefer inspect polling.
- cancel: cancel a running run.
- create: save source to disk. scope "project" → .opencode/workflows/<name>.ts, "global" →
  <global-config>/workflows/<name>.ts. Never overwrites.

# RESUME
- Resume: start with resume_of: "<runId>". Completed agents replay instantly from cache when their
  key (prompt + label + agent + model + effort + schema + phase) is unchanged — reordering or
  inserting calls is safe; only genuinely new/changed agents re-run. Cached nodes show cached:true
  and cost 0. Force re-runs with invalidate_agents (labels or keys) or ctx.invalidatePhase(name).
- Resumable statuses: paused, interrupted, failed, completed.
- If the user explicitly set a budget and BudgetExceededError fires, resume with resume_of after
  raising/removing the cap — all completed work replays free from cache.

# TEMPLATE-LITERAL TRAP (the #1 cause of syntax errors — READ THIS)
Prompts are backtick strings. Every ${...} inside them is evaluated when the FILE loads, not sent
to the subagent.
1. Interpolate ONLY variables that exist in run() scope: `${args.dir}`, `${file}`, `${c.issue}`.
2. Example code inside a prompt must be escaped: write \${notARealVariable} so the subagent
   receives the literal ${...}. Or put generated-code samples in single-quoted strings.
3. `${x or y}` is not JavaScript. Write `${x} or y`, or `${x || "y"}`.
4. Validate before starting: `bun --check <file>.ts` must exit 0. The engine refuses to run files
   with syntax errors and reports line:col plus an escaping hint.

# QUALITY PATTERNS (use these by default, not as extras)
- Adversarial verify: ≥3 independent agents try to REFUTE each finding; survive on ≥2 support.
- Perspective-diverse verify: each verifier gets a distinct lens (correctness, security, perf,
  reproducibility).
- Judge panel: N independent solutions from different angles (MVP-first, risk-first, perf-first),
  then a judge agent scores and synthesizes the best of all.
- Loop-until-dry: keep discovering/fixing until 2 consecutive rounds find nothing new.
- Multi-modal sweep: parallel agents search the same target by-file, by-content, by-entity,
  by-history simultaneously.
- Completeness critic: final agent asks "what's missing?" before every report.
Data flows via closure variables and setPhase payloads — chain them explicitly, as in the example.

# TROUBLESHOOTING (auto-fix, in order)
1. "Workflow syntax error <file> line:col": almost always an unescaped ${} in a prompt. Read the
   file, apply the trap rules above, `bun --check`, retry start.
2. "Cannot find module '.cache-*.ts'": temp-import issue. First run `bun --check` (hidden syntax
   error is the usual real cause). If it passes, it's a transient file lock (Windows AV): the
   engine retries automatically; if it persists, delete `.opencode/workflows/.cache-*` orphans
   and retry.
3. "Missing meta export" / "missing run function": file must export default {meta, run} (or
   `export const meta` + `export default {run}`), and meta must be literal-only.
4. InvalidPhaseError: a setPhase() title doesn't match meta.phases — fix the typo or add the phase.
5. Determinism lint error: remove Date.now()/Math.random()/new Date(), pass values via args, or
   set meta.allowNondeterminism: true if truly needed.

- [ ] Only run()-scope variables are unescaped ${} in prompts
- [ ] Every agent has a unique, stable label

- [ ] No Date.now()/Math.random() in the script
